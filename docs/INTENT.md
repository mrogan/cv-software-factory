# Intent

Why Software Factory exists and what it has to prove, in one page. The [specification](SPECIFICATION.md) says what to build; this says what it is for. When a choice isn't settled by the spec, settle it here.

## Why it exists

I'm Martin Rogan, and I'm looking for my next role. I would rather show what I can do than describe it, so this project is my portfolio: a working system that a recruiter, an engineer or an interviewer can open and judge for themselves.

## What it has to prove

1. **I build with agents today.** Agentic development as a working practice, not a demo trick: agents write the code, deterministic gates decide what ships, and people own the rules. It is safe because of mechanisms, not because the prompts ask nicely.
2. **I run delivery the way it is heading.** GitOps, a signed supply chain, admission control, progressive delivery and verification from telemetry, on Kubernetes, portable from a laptop to DigitalOcean to AWS. My day job hasn't needed it yet, so I built it here.
3. **I make complex things simple.** In the interface, in the code and in the docs. The factory is complicated; understanding it should not be.

## The product is everything a reviewer touches

The factory is only part of it. Each of these is judged on its own:

| | The bar |
|---|---|
| **The console** | Exquisite, with real personality and flair. Someone who has never heard of a canary understands one in a minute. |
| **The code and the repo** | Best practice and scrupulous hygiene, visible in every commit, PR, workflow and README. Small, clear parts over clever ones. |
| **The factory** | Production-ready, not a mock-up. And an outstanding demo: it fixes real defects while people watch. |

## How to decide

- **Simple beats clever.** If a part can't be explained on one screen, simplify the part before improving the explanation.
- **Real beats simulated.** Every fix, refusal and rollback shown is the actual mechanism at work. Nothing is animated to look like it worked.
- **The details are the pitch.** Empty states, error messages, commit messages and log lines are read by the same people who read the headline.
- **Finished beats broad.** A smaller thing done exquisitely is worth more than a larger thing done adequately. Cut scope before cutting quality.
- **Cheap and easy to switch off.** Hard spend caps, one command to stop everything.

## Who should leave with what

- **A recruiter**, in one minute: this person builds things that work and explains them well.
- **An engineer**, in half an hour: this is how I would want agents let loose on my own systems.
- **An interviewer**, in an hour: this person can design, build and run a platform, and knows where the risks are.
